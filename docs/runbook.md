# 值班手册（Runbook）

## 一、服务概况

| 项 | 内容 |
|----|------|
| 服务 | ecom-ai-cs（电商 AI 客服对话服务） |
| 当前版本 | v0.1.0 |
| 核心链路 | 用户消息 → 意图识别 → 知识检索 → 回答 / 转人工 |
| 商业红线 | 任何不确定场景必须转人工，禁止编造答案 |

## 二、告警分级与响应时限

| 级别 | 现象 | 响应时限 | 处理方式 |
|------|------|---------|---------|
| S0 | 对话无响应 / 转人工失败 / 答错订单信息 | 15 分钟内响应 | 立即 hotfix，必要时先回滚 |
| S1 | 某类意图回答质量明显下降 | 2 小时内 | 当天修复，走正常 PR |
| S2 | 偶发错误、日志异常 | 次工作日 | 排进迭代 |

## 三、S0 故障处理流程（背下来）

```
1. 确认影响面：多少商家、多少会话受影响
2. 先止血，再查因
   - 有回滚开关 → 立即回滚到上一个 tag
   - 没有开关 → 走 hotfix 通道（见 CONTRIBUTING.md 第 8 节）
3. 拉群同步：问题现象 / 影响范围 / 预计恢复时间（每 15 分钟更新一次）
4. 修复后验证：跑评测集 + 手动试最难的那几个 case
5. 24 小时内补：Issue 单 + 复盘文档 docs/postmortem/
```

## 四、常见故障速查

| 现象 | 优先排查 | 常用命令 |
|------|---------|---------|
| 机器人回答"人工客服"过多 | 知识库是否为空 / 检索阈值是否过高 | `python scripts/run_eval.py -v` |
| 答错订单号 | 订单号正则是否误抓（如把金额当订单号） | `pytest tests/test_intent.py -q` |
| 服务起不来 | 依赖、端口、环境变量 | `python -m ecom_cs.cli "测试"` |
| 转人工按钮无响应 | 前端 SDK / 转人工接口 | 查看 `need_human` 字段是否返回 |

## 五、回滚步骤

```bash
git checkout main && git pull
git log --oneline -5          # 找到上一个可用版本
git tag                        # 确认历史版本号，如 v0.1.0
gh release view v0.1.0         # 或用网页查看该版本发布说明
# 部署系统里将生产镜像切回 v0.1.0
```

## 六、值班交接模板（每天 18:00）

```
【交接】11-10 白班 → 夜班
- 当前线上版本：v0.1.1
- 今日故障：1 起（S1，物流意图未识别"几天能到"，已修复待发布）
- 待观察：灰度商家 A 的转人工率，昨日 21%，今日 18%
- 明日待办：REQ-101 猜你想问联调
```
